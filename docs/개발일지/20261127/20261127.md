# 1. 객체지향 프로그래밍

## 객체지향이란?

객체지향 프로그래밍은 프로그램을 서로 역할을 가진 여러 **객체**로 나누어 만드는 방법입니다.

예를 들어 게임에서 등장하는 것은 다음과 같습니다.

- 슬라임
- 궁수
- 보스
- 포탄
- 아이템

이들은 이름, 체력, 위치처럼 가지고 있는 정보와 공격, 이동처럼 수행하는 행동이 서로 다릅니다.

## 클래스와 객체

- **클래스**는 객체를 만들기 위한 설계도입니다.
- **객체**는 설계도를 바탕으로 실제로 만들어진 실체입니다.

예를 들어 `슬라임` 클래스가 있다면, 실제 게임에 등장하는 여러 슬라임은 모두 이 클래스로 만들어지는 객체입니다.

```csharp
class Slime
{
    public string Name;
    public int HP;
    public int X;
    public int Y;

    public void Move()
    {
        // 이동 처리
    }

    public void Attack()
    {
        // 공격 처리
    }
}
```

## DRY 원칙

**DRY는 Don't Repeat Yourself의 약자입니다.**

같은 코드를 여러 곳에 복사해서 사용하지 말고, 공통 기능은 한 곳에 모아서 재사용하라는 의미입니다.

예를 들어 슬라임과 궁수가 모두 기본 공격을 가졌다면 기본 공격 코드를 매번 다시 작성하는 것이 아니라 공통 부분으로 묶을 수 있습니다.

# 2. 추상 클래스

## 추상 클래스란?

추상 클래스는 여러 클래스의 공통 규칙을 모아 둔 설계도입니다.

하지만 추상 클래스만으로는 실제 객체를 만들 수 없습니다.

예를 들어 스타크래프트의 유닛은 모두 다음과 같은 공통 정보가 있습니다.

- 이름
- 체력
- 이동 능력
- 지상 또는 공중
- 생체 또는 기계

이 공통 규칙을 `Unit` 추상 클래스에 정리할 수 있습니다.

```csharp
abstract class Unit
{
    public string Name;
    public int HP;

    public abstract void Move();
    public abstract void Attack();
}
```

그 다음 실제 유닛은 추상 클래스를 상속받아 만든 클래스입니다.

```csharp
class Marine : Unit
{
    public override void Move()
    {
        // 마린 이동
    }

    public override void Attack()
    {
        // 마린 공격
    }
}
```

`Marine`은 `Unit`을 상속받았기 때문에 “마린은 유닛이다”라고 자연스럽게 표현할 수 있습니다.

즉, 추상 클래스는 다음 질문에 답할 때 사용합니다.

> 이것들은 본질적으로 무엇인가?

예를 들어:

- 마린은 유닛이다.
- 질럿은 유닛이다.
- 화살 타워는 타워이다.
- 대포 타워는 타워이다.

# 3. 상속과 인터페이스

## 상속이란?

상속은 한 클래스의 기능을 다른 클래스가 물려받는 것을 말합니다.

상속 관계는 다음처럼 표현할 수 있습니다.

- Marine **is a** Unit → 마린은 유닛이다.
- Archer **is a** Unit → 궁수는 유닛이다.
- ArrowTower **is a** Tower → 화살 타워는 타워이다.

따라서 공통된 본질과 기본 기능이 있다면 상속을 사용합니다.

보스가 기본 공격을 유닛마다 조금씩 다른 방식으로 한다면 상속받은 함수를 보스만의 방식으로 다시 작성할 수 있습니다.

이를 **오버라이드(override)**라고 합니다.

```csharp
class Boss : Unit
{
    public override void Attack()
    {
        // 보스만의 특별한 공격
    }
}
```

상속은 본질적으로 같은 종류일 때 사용합니다.

## 인터페이스란?

인터페이스는 특정 능력이나 행동을 할 수 있다는 규칙을 정하는 틀입니다.

상속 관계가 아니라 능력 관계일 때 사용합니다.

- 유닛은 은폐 가능하다.
- 유닛은 탐지 가능하다.
- 유닛은 수송 가능하다.
- 유닛은 일꾼이다.

이 관계는 다음처럼 표현할 수 있습니다.

- Marine **can** Attack
- Medic **can** Heal
- Dropship **can** Transport

예를 들어 은폐 기능이 필요한 유닛만 선택적으로 구현할 수 있습니다.

```csharp
interface ICloakable
{
    void Cloak();
}

class Ghost : Unit, ICloakable
{
    public override void Move() { }
    public override void Attack() { }

    public void Cloak()
    {
        // 은폐 기능
    }
}
```

유닛마다 있는지 없는지를 `if`문으로 처리하는 것은 비효율적일 수 있습니다.

오히려 해당 능력이 있는 유닛이 인터페이스를 구현하는 편이 더 분명하고 확장하기 쉽습니다.

## 추상 클래스와 인터페이스 비교

| 구분 | 추상 클래스 | 인터페이스 |
|---|---|---|
| 표현하는 관계 | A는 B이다 | A는 B를 할 수 있다 |
| 판단 기준 | 본질적으로 무엇인가 | 어떤 능력을 가지는가 |
| 예시 | 마린은 유닛이다 | 마린은 은폐할 수 있다 |
| 키워드 | 상속 | 구현 |
| C# 문법 예시 | `class Marine : Unit` | `class Ghost : Unit, ICloakable` |

간단히 기억하면 다음과 같습니다.

- **A is B**이면 상속을 사용합니다.
- **A can B**이면 인터페이스를 사용합니다.

# 4. 설계할 때 구분하는 기준

| 대상 | 판단 기준 | 예시 |
|---|---|---|
| 추상 클래스 | 공통된 본질과 기본 규칙 | 유닛, 타워 |
| 상속 클래스 | 같은 종류에 속하지만 행동이 다른 경우 | 마린, 질럿, 화살 타워 |
| 인터페이스 | 선택적으로 사용할 수 있는 능력 | 은폐, 수송, 탐지 |
| 변수 또는 값 | 행동은 같고 상태나 수치만 다른 경우 | 체력, 이동 속도, 지상 여부 |
| 독립 클래스 | 다른 클래스와는 별개의 존재 | 포탄, 아이템 |

예를 들어 포탄은 유닛이나 타워를 상속받아야 하는 대상이 아니라 별도로 움직이고 충돌하는 독립적인 객체입니다.

# 5. 자료구조와 알고리즘

## 자료구조란?

자료구조는 데이터를 효율적으로 저장하고 사용하는 방법입니다.

예를 들어 다음은 모두 자료구조입니다.

- 배열
- 리스트
- 스택
- 큐
- 해시 테이블
- 해시 셋

자료구조는 상황에 따라 선택합니다.

- 순서대로 추가하거나 관리할 때는 리스트
- 나중에 넣은 것을 먼저 꺼낼 때는 스택
- 먼저 넣은 것을 먼저 꺼낼 때는 큐
- 빠르게 포함 여부를 확인할 때는 해시 셋
- 이름이나 키로 값을 빠르게 찾을 때는 해시 테이블

## 왜 자료구조를 선택하는가?

같은 데이터를 저장해도 자료구조에 따라 처리 속도와 필요한 메모리가 달라질 수 있습니다.

선택할 때는 다음 두 가지를 함께 고려합니다.

- 시간 효율: 빠르게 처리할 수 있는가?
- 공간 효율: 메모리를 적게 사용하는가?

보통은 둘 중 하나를 더 중요하게 사용합니다.

- 시간을 줄이려면 데이터를 추가로 저장하는 공간을 더 사용할 수 있습니다.
- 공간을 줄이려면 데이터를 찾는 데 더 많은 시간이 필요할 수 있습니다.

## 예시

```csharp
List<int> numbers = new List<int>();
```

위 코드는 데이터를 순서대로 관리하는 리스트 자료구조를 사용하겠다는 의미입니다.

```csharp
HashSet<int> numbers = new HashSet<int>();
```

위 코드는 중복 없는 데이터를 빠르게 관리할 수 있는 해시 셋 자료구조를 사용하겠다는 의미입니다.

문제에 따라 적절한 자료구조를 선택하는 것은 알고리즘을 효율적으로 만드는 중요한 방법입니다.

# 6. 빅오 표기법

## 빅오 표기법이 필요한 이유

프로그램의 성능을 컴퓨터나 실행 환경에 관계없이 비교하기 위해 빅오 표기법을 사용합니다.

실행 시간을 직접 측정하면 컴퓨터 사양에 따라 달라질 수 있습니다.

예를 들어:

- 5070Ti에서 5ms
- 1660에서 30ms

같은 작업이라도 그래픽 카드뿐 아니라 CPU와 환경에 따라 시간이 달라집니다.

그래서 빅오 표기법은 실제 시간을 측정하지 않고 **데이터의 개수가 늘어났을 때 얼마나 많은 작업을 해야 하는지**를 비교합니다.

## 주요 빅오 표기법

| 표기법 | 의미 | 예시 |
|---|---|---|
| $O(1)$ | 데이터 개수와 관계없이 한 번에 처리 | 배열의 특정 위치 접근 |
| $O(n)$ | 데이터 개수만큼 한 번씩 확인 | 리스트를 앞에서부터 순회 |
| $O(n^2)$ | 데이터 개수를 두 번 반복해서 확인 | 중첩 반복문 비교 |
| $O(log n)$ | 한 번 확인할 때마다 범위를 절반으로 줄임 | 이진 탐색 |

예를 들어 데이터가 100개일 때와 100만 개일 때 모두의 수를 비교하려면 다음과 같이 계산 횟수의 차이를 살펴봅니다.

- 데이터가 100개일 때 100번 확인
- 데이터가 100만 개일 때 100만 번 확인

이때 실행 결과 시간보다 중요한 것은 데이터가 늘어날수록 처리 횟수가 얼마나 빠르게 증가하느냐입니다.

정답은 빅오 표기법의 이름처럼 `Big-O` 표기법이지만, 오늘은 이해하기 쉽게 “빅오 표기법”으로 불렀습니다.

# 7. 자료구조별 특징

## 스택

스택은 나중에 들어온 데이터를 먼저 꺼내는 구조입니다.

- 이름: LIFO
- 의미: Last In, First Out
- 비유: 접시를 위에서부터 하나씩 꺼내는 구조

브라우저의 뒤로 가기 기능이나 함수 호출 기록 같은 작업에 사용할 수 있습니다.

## 큐

큐는 먼저 들어온 데이터를 먼저 꺼내는 구조입니다.

- 이름: FIFO
- 의미: First In, First Out
- 비유: 은행이나 마트의 줄 서기

대기열이나 순서대로 처리해야 하는 작업에 사용할 수 있습니다.

## 해시 테이블

해시 테이블은 키와 값을 짝으로 저장하고 키를 이용해 값을 빠르게 찾는 자료구조입니다.

예를 들어:

- 키: 사용자 이름
- 값: 사용자 점수

이름을 알면 점수를 빠르게 찾을 수 있습니다.

평균적으로 검색이나 추가 작업은 빠르기 때문에 때로는 $O(1)$에 가깝게 동작합니다.

## 해시 셋

해시 셋은 중복 없는 값을 빠르게 저장하고 확인하는 자료구조입니다.

예를 들어 이미 방문한 위치를 저장할 때 사용할 수 있습니다.

- 특정 위치를 이미 방문했는가?
- 처음 방문하는 위치인가?

이런 문제에는 해시 셋이 적합할 수 있습니다.

# 오늘의 정리

1. 클래스는 객체를 만들기 위한 설계도다.
2. 추상 클래스는 공통된 본질과 기본 규칙을 모은다.
3. 상속은 “A is B” 관계에 사용한다.
4. 인터페이스는 “A can B” 능력 관계에 사용한다.
5. 포탄이나 아이템처럼 독립적인 대상은 별도의 독립 클래스로 만든다.
6. 자료구조를 선택할 때는 시간과 공간의 효율을 함께 고려한다.
7. 빅오 표기법은 데이터가 커질 때 처리 횟수가 얼마나 증가하는지 비교하는 방법이다.
8. 스택은 나중에 넣은 것을 먼저 꺼내고, 큐는 먼저 넣은 것을 먼저 꺼낸다.
