1. 오늘 배운 내용 (Summary)

오늘 새롭게 알게 된 개념이나 기술을 핵심 위주로 정리합니다.
• 클래스와 객체: 클래스는 데이터(필드)와 동작(메서드)을 정의한 설계도이며, new로 생성한 객체(인스턴스)는 메모리에 실물로 할당되는 참조 형식(Reference Type)이다.
• 클래스 주요 멤버:
	• 필드 & 속성: 데이터는 private 필드로 숨기고, 속성(get, private set, init, 계산 속성 =>)을 통해 외부 접근 규칙을 제어한다.
	• 생성자 & static: 생성자(: this(...) 연결 가능)로 객체의 초기 상태를 보장하며, static 멤버는 개별 객체가 아닌 클래스 전체가 하나만 공유한다.
• 객체지향의 4대 기둥:
	• 캡슐화 (Encapsulation): 상태를 변경하는 통로를 특정 메서드나 속성 하나로 제한하여 데이터 무결성(예: HP 음수 방지)을 지킨다.
	• 상속 (Inheritance): 공통 기능은 부모 클래스에 두고(base), 자식 클래스에서 확장한다(단일 상속만 가능, "~이다" 관계).
	• 다형성 (Polymorphism): virtual과 override를 사용하면 컴파일 시점의 변수 타입이 아닌 실행 시점의 실제 객체를 기준으로 메서드가 호출된다.
	• 추상화 (Abstraction): 공통 뼈대를 제공하는 abstract class와 다중 구현이 가능한 능력 약속("~할 수 있다")인 interface로 역할을 분리한다.
csharp
// 캡슐화, 다형성, 인터페이스 적용 예시
public interface IDamageable
{
    void TakeDamage(int amount);
}

public abstract class Enemy : IDamageable
{
    public int Hp { get; private set; } // 캡슐화: 외부 직접 수정 방지

    protected Enemy(int hp) => Hp = hp;

    public void TakeDamage(int amount)
    {
        Hp = Math.Max(0, Hp - amount); // 변경 통로를 하나로 통일
    }

    public virtual string Attack() => "기본 공격";
}

public class Boss : Enemy
{
    public Boss() : base(500) { }
    public override string Attack() => "불꽃 브레스"; // 다형성: 실제 객체 기준 실행
}


2. 문제 상황 및 해결 과정 (Troubleshooting)

개발 또는 학습 중 마주친 에러나 막혔던 부분과 해결 방법을 기록합니다.
• 문제 상황:
	1. 객체 없이 적의 이름, 체력, 좌표를 별도의 List로 각각 관리할 때, 특정 인덱스의 요소를 하나만 지우는 것을 누락하면 데이터가 서로 어긋나는 버그가 발생한다.
	2. 다형성을 의도하고 자식 클래스 메서드에 override 대신 new를 쓰거나 생략하면, 부모 타입 변수로 호출할 때 자식 메서드가 실행되지 않는다(경고 CS0114).
• 원인 분석:
	1. 연관된 데이터와 그 데이터를 다루는 규칙이 분리되어 있어 외부에서 값을 임의로 조작(hp = -50)하거나 동기화가 깨지기 쉽다.
	2. new 키워드는 메서드를 재정의하는 것이 아니라 이름만 같은 별개의 메서드로 숨기는 동작이므로 컴파일 시점의 선언 형식을 따른다.
• 해결 방법:
	1. 관련된 데이터와 로직을 하나의 클래스로 묶고, 필드를 private으로 감춘 뒤 검증 로직(Math.Clamp 등)이 포함된 메서드로만 상태를 변경하도록 캡슐화한다.
	2. 실제 객체에 맞는 동작을 실행하려면 부모 메서드에 virtual, 자식 메서드에 override를 명시한다.

• 좋았던 점 / 배운 점: 단순히 문법을 외우는 것을 넘어, 게임 개발에서 리스트를 따로 관리할 때 생기는 치명적인 버그를 객체지향이 어떻게 해결하는지 체감할 수 있었다. 특히 폭발 범위 공격처럼 부모 클래스가 전혀 다른 객체(적, 플레이어, 나무 상자)들을 IDamageable 인터페이스 하나로 묶어 처리하는 설계가 인상 깊었다.
